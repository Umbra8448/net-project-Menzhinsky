## Протокол

Сервер слушает порт **<9000>**. Каждая команда — одна строка, каждый ответ — одна строка. После подключения сервер присылает приветствие.

| Команда | Что делает | Пример ответа |
|---|---|---|
| `<ADD text>` | <добавить в список> | `<Server: OK, task 1>` |
| `<LIST>` | <вывод списка> | `<Server: 1) BURMALDA>` |
| `<DEL <number>>` | <удалить элемент списка> | `<Server: OK, task deleted>` |
| `HELP` | список команд | `<...>` |
| `QUIT` | завершить работу | `BYE` |

Ошибки: <Server: ERROR invalid task number>.

## Ответы на контрольные вопросы

<1. В каком порядке сервер вызывает socket, bind, listen, accept?
Сервер вызывает их по порядку:

socket() — создаёт сокет для связи.

bind() — привязывает сокет к IP-адресу и порту.

listen() — начинает ждать подключения клиентов.

accept() — принимает подключение клиента.

2. Почему клиенту не нужны bind и listen? Какой порт получает клиент?
Клиенту не нужен bind(), потому что операционная система сама выбирает ему свободный порт.

listen() не нужен, потому что клиент не ждёт подключения, а сам подключается к серверу.

Клиент получает случайный свободный порт.

3. Зачем нужен htons(PORT)?
htons() переводит номер порта в сетевой порядок байтов.

Это нужно, чтобы разные компьютеры правильно понимали номер порта.

4. Почему recvLine читает до символа \n, а не вызывает recv один раз?
Потому что recv() не гарантирует, что получит всё сообщение сразу.

Сообщение может прийти частями.

Поэтому recvLine читает данные, пока не встретит \n — конец строки.

5. Описание:

Клиент отправляет серверу команды:

ADD — добавить задачу.

LIST — показать все задачи.

DEL — удалить задачу по номеру.

QUIT — завершить соединение.

Сервер выполняет команду и отправляет ответ клиенту.

Если команда неправильная или данные введены неверно, сервер отправляет сообщение об ошибке (ERROR).

После команды QUIT сервер отправляет BYE и закрывает соединение.>
